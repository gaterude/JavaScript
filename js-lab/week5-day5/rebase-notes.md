# Merge vs Rebase

A merge joins two branches and usually creates a separate merge commit when the branches have diverged. A rebase takes commits from a feature branch and replays them on top of another branch, creating a linear history. I would use merge when I want to combine completed work while preserving the history of how branches came together. I would use rebase on my own feature branch when I want to update it with the latest changes from main. The golden rule is never to rebase a public branch that other people have based their work on. In this exercise, my feature branch had two commits while main received an independent commit. Rebasing placed my two feature commits after the updated main commit. The result was a linear history without an additional merge commit.
